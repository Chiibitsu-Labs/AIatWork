Turn on the memory

The part that makes your AI stop forgetting you.

Your vault already came with an “improve” skill. It's the thing that, at the end of a work session, jots down what your AI learned about you — how you like things, decisions you made, mistakes to not repeat — and reads it back next time.

On Claude & ChatGPT (website / app)

Both now have a Skills feature — you're adding one so the AI knows to save lessons when you ask it to. Easiest way, now that your connector's already hooked up: open a chat with Claude or ChatGPT and say "read .claude/skills/improve/SKILL.md from my vault and show me the whole file, ready to paste." It'll fetch the exact text for you — no digging through GitHub. Then: Settings → Skills → Add a skill, name it improve, paste in what it gave you, save. From then on, ask it to “save what we learned” and it reads past notes at the start of a chat, too.

🪄

Honest note: on the websites/apps, the memory runs when the AI decides it's relevant or when you nudge it — a strong habit, not a guarantee. Claude Code (below) upgrades the loading half to genuinely automatic — every session starts with your history already read in, no prompting needed. The saving half is still a nudge there too, just a more insistent one (it asks itself at the end of every session, rather than waiting for you to remember) — not a guarantee that a note gets written.

Want session-start loading to be fully automatic? (10 min, Claude Code)

Claude Code is Anthropic's free tool that runs in your computer's Terminal. Your vault ships with the automation already written (a .claude/ folder with the hooks + the improve skill) — once one small helper is installed, you just run Claude Code from your vault folder and the "load past notes" half is fully automatic: every session starts with your history already read in, no action needed. The "capture new lessons" half is a nudge, not a guarantee — at the end of a session it asks the AI "was there anything worth saving?" and the AI decides; if nothing stood out (or it's missed), no note gets written that session, and that's fine — it's not silently failing, there was just nothing to capture.

  1. Do the Phase 6 step first so your vault is a folder on your computer.
  2. Install Claude Code (free): claude.com/product/claude-code — follow its installer for Mac or Windows.
  3. Install jq, the tiny helper the memory hooks use to read Claude Code's messages (it isn't preinstalled). Mac: run brew install jq (no Homebrew yet? brew.sh is one paste). Windows: run winget install jqlang.jq. If you skip this nothing breaks — the hooks notice jq is missing and stay quiet, so Claude Code still works, just without the automatic capture.
  4. Windows only: the hook scripts also need a Bash shell, which plain PowerShell doesn't have. Install Git for Windows (free) — this is a separate download from GitHub Desktop, which doesn't include it. It adds a Git Bash option to your Start menu; use that instead of PowerShell for the next step.
  5. Open Terminal Mac / Git Bash Windows, go to your vault folder, and start it:
cd path/to/your-vault claude

That's it — from now on, any conversation you have in that folder remembers you automatically. (Not doing this is totally fine; the website/app memory above still works, just with a nudge instead of on its own.) Chiibitsu Labs can screen-share this with you if the Terminal part feels unfamiliar.

For your IT / CTO

The “why does this touch GitHub?” question, answered directly.

This is not a GitHub source-code integration. Nobody is giving an AI access to your company's repositories. Here's what's actually happening:

  • The user's personal notes are stored as plain text files. We use one private GitHub repository as the storage for those files — GitHub is acting purely as a filing cabinet, not as a code platform.
  • The AI never talks to GitHub directly. It talks to a small, single-purpose connector (running on the user's own Vercel account) that can do exactly three things: read a note, write a note, list notes — in that one repository only.
  • The credential involved is a fine-grained token scoped to that single repo, with “Contents” permission and nothing else. It cannot read other repositories, cannot see organization settings, cannot touch code.
  • Connecting an AI requires a human-held passphrase; AIs receive a 30-day expiring token, never a permanent master credential.
🛡️

Blast-radius summary for a review: worst case if the connector or its token fully leaked is exposure of one user's personal notes repo — no code, no other repos, no org access. Every off-switch (revoke token, rotate signing secret, delete the Vercel project) is in the user's hands.

Data-flow honesty: when the AI reads a note, that note's text passes through Anthropic or OpenAI (or Google, for the Gemini/NotebookLM options) — identical to a user pasting the note into a chat. The integration changes how conveniently notes move, not which AI providers process them. Evaluate it under the same policy you'd apply to staff using these AI tools at all.

Training data, specifically: on Claude Team/Enterprise and ChatGPT Team/Business/Enterprise/Edu — the workspace tiers this section is written for — neither Anthropic nor OpenAI use your prompts or outputs to train models, by default, with no toggle needed; it's a contractual term of those plans. Personal accounts are a different story: Claude Free/Pro/Max and ChatGPT Free/Plus/Pro default to training-eligible, and you have to turn it off yourself (Claude: Settings → Privacy; ChatGPT: Settings → Data controls → “Improve the model for everyone”). Two caveats even after opting out: Anthropic can still use a conversation it flags for safety review regardless of your setting, and on ChatGPT a thumbs-up/down vote on a specific reply authorizes that chat for training even with the toggle off. If anyone on the team is connecting from a personal account rather than the workspace, that's the setting to check.

What keeps it safe

It's yours, end to end

Notes in your private GitHub repo, connector on your free Vercel account. No middleman service.

A human approves each connection

The passphrase means “anyone with the link” never equals “anyone with access.”

AI gets a temporary key

Claude/ChatGPT receive a 30-day key that expires — never your master key.

Small blast radius

The GitHub token can touch only this one notes repo. You hold every off-switch.

The AI can't delete a file

The connector can only read, list, and write — there's no delete tool, so a file can never be removed from the repo. Writing can still overwrite a file's content, though; if that happens, recover it from the version history in the next card.

Every change is undoable

Each write is a saved version in GitHub. A bad edit is a one-click roll-back with the full before/after.

💾

Backups, if you want belt-and-suspenders: your vault ships with two optional auto-backups (see BACKUP.md) — weekly dated restore points (on by default) and an off-GitHub mirror to a second host (opt-in). Plus, git history alone already lets you restore any note to any past version.

If something's stuck

The deploy failed right away

Almost always the “Root Directory” wasn't set to vault-mcp. In the Vercel project → Settings → General → Root Directory → set it to vault-mcp → redeploy.

Vercel is asking me about plans/pricing

For a personal, one-person vault: choose the Hobby (free) option — this kit fits comfortably in the free tier, no card needed. Hobby is for personal, non-commercial use only — if this vault is for a company or team (see Companies & teams), use a paid Pro or Team plan instead; Vercel's terms don't permit business use on Hobby.

Connecting the AI shows a “Server not configured” / 503 message

The running deployment can't see VAULT_OWNER_PASSPHRASE or OAUTH_SIGNING_SECRET (the message names both even if only one is missing). In Vercel → Settings → Environment Variables, open each one and check: exact spelling, the Production checkbox is ticked, the value has no NAME= prefix or quotes, and the signing secret is the long value (32+ characters). Then redeploy the deployment labeled “Production” — not the newest one in the list, which may be a preview.

I set the keys and redeployed, but nothing changed

You probably redeployed a preview. In the Deployments tab, previews from branches sit above production. Find the one tagged Production → ⋯ → Redeploy. Keys apply only to deploys made after they were saved, per environment.

The deploy button says the repository name is taken

You (or the button, earlier) already created it. Either pick a new name — and remember VAULT_REPO must match it — or delete the half-made repo on GitHub and run the button again.

GitHub is forcing me to set up 2FA

That's GitHub's normal account security, not part of this setup. Use your phone's authenticator app; it takes two minutes and protects your vault too.

There's no box to paste a password/token in Claude or ChatGPT

That's correct — those apps only offer OAuth. Paste just the web address, leave the OAuth fields empty, and the passphrase window appears after you click Add/Create.

The AI says it can't find my files

Check VAULT_OWNER (your GitHub username) and VAULT_REPO (your repo name) are set correctly in Vercel, and that your VAULT_GITHUB_TOKEN has that repo selected with Contents: Read and write. Fix, redeploy.

Claude added the connector but doesn't seem to use it

Start a fresh chat, and check the tools menu (the ⚙/plug icon near the message box) shows your connector switched on for that chat. Then ask the test question again.

ChatGPT's plugin page says “No app actions available yet”

Normal before first use — open a chat and ask “list the files in my vault root.” It wakes on the first real call (or hit Refresh on that page).

I can't find Developer mode in ChatGPT

On Business/Enterprise/Edu workspaces, only an Admin can switch it on. On a personal Plus/Pro account you can switch it on yourself — it's just limited to read-only there (see Phase 4), so if you can't find the toggle at all, double-check you're on Plus or higher; the free tier has no Developer mode.

I forgot my passphrase

No reset needed — set a new value for VAULT_OWNER_PASSPHRASE in Vercel, redeploy Production, and use the new one from then on. Already-connected AIs keep working; only new connections ask for it.

The AI suddenly says “Unauthorized” after weeks of working

The AI's 30-day key expired — that's by design. Reconnect (Claude: the connector's menu → reconnect; ChatGPT: the plugin's page → reconnect), type the passphrase, done.

Notes I write on my phone aren't showing up

Phone sync is its own step — see Phase 6's iPhone options (Obsidian Sync or Working Copy). Until then, notes written by the AI from your phone do land in the vault — it's only Obsidian-on-phone edits that need the sync step.

The first reply after a quiet day is slow

Free-tier servers nap when idle and wake in a second or two. The first call warms it up; everything after is fast. Nothing is wrong.

I want automatic memory in Claude Code (advanced)

See the “Want it fully automatic?” steps inside Phase 5 — install Claude Code (free), install the small jq helper, then run it from your vault folder. Loading past notes at session start is fully automatic; saving new ones is a nudge the AI acts on, not a guarantee (it asks itself "anything worth saving?" at the end of each session). The automation is already written into your vault; the only thing to add is jq (Phase 5 has the one-line command), and if it's missing the memory just stays quiet rather than erroring. Chiibitsu Labs can screen-share the Terminal part with you.

I accidentally made the vault repo public

GitHub → your repo → Settings → scroll to Danger Zone → Change visibility → Private. Do it promptly and you're fine.

How do I turn the whole thing off?

Three off-switches, any one works: remove the connector/plugin in the AI's settings (stops that AI), delete the Vercel project (stops all AI access), or revoke the GitHub token (stops everything at the source). Your notes stay safe in the repo through all of them — and you can download the whole vault anytime via GitHub → Code → Download ZIP.
