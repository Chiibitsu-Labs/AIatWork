If something’s stuck

The deploy failed right away

Root Directory probably isn’t vault-mcp. Vercel project → Settings → General → Root Directory → vault-mcp → redeploy.

Vercel is asking about plans or pricing

Personal vault: choose Hobby (free, no card). Company or team vault: Vercel’s terms need a paid Pro or Team plan.

“Repository name is taken”

It was already made. Pick a new name (and use it for VAULT_REPO), or delete the half-made repo on GitHub and try again.

GitHub wants me to set up 2FA

Normal GitHub security. Use your phone’s authenticator app — two minutes, and it protects your vault too.

“Server not configured” / 503 when connecting

Vercel can’t see VAULT_OWNER_PASSPHRASE or OAUTH_SIGNING_SECRET. In Vercel → Settings → Environment Variables, check spelling, that Production is ticked, and no quotes or NAME= in the value. Then redeploy the deployment labeled Production.

I changed a key and redeployed, but nothing changed

You probably redeployed a preview. In Deployments, find the one tagged Production → ⋯ → Redeploy.

There’s no box for a password or token

Correct — paste only the address, leave OAuth fields empty. The passphrase window opens after you click Add.

The AI can’t find my files

Check VAULT_OWNER (your GitHub username) and VAULT_REPO (your repo name) in Vercel, and that your GitHub key has that repo selected with Contents: Read and write. Fix, then redeploy.

Claude added it but doesn’t use it

Start a fresh chat. In the tools menu near the message box, make sure your connector is switched on. Ask again.

ChatGPT doesn’t use it

Start a fresh chat. Click ＋ near the message box and make sure your vault is turned on for that chat. If the plugin page says “No app actions available yet,” just ask the test question once — it wakes on first use.

I forgot my passphrase

Set a new VAULT_OWNER_PASSPHRASE in Vercel, redeploy Production, use the new one. Connected AIs keep working.

“Unauthorized” after weeks of working

The AI’s 30-day key expired, by design. Reconnect in the connector/plugin settings and type your passphrase.

The first reply after a quiet day is slow

Free servers nap when idle. The first call wakes it up. Nothing’s wrong.

I made the vault public by accident

GitHub → your repo → Settings → Danger Zone → Change visibility → Private.

How do I turn it all off?

Any one works: remove the connector in the AI’s settings, delete the Vercel project, or revoke the GitHub key. Your notes stay safe in the repo.

What keeps it safe

  • It’s yours. Notes in your private GitHub repo, connector on your own Vercel account. No middleman.
  • A human approves each connection. Nobody connects an AI without your passphrase.
  • The AI gets a 30-day key, never your master key.
  • Small blast radius. Your GitHub key touches only this one repo.
  • The AI can’t delete files. It can only read, list and write.
  • Every change is undoable. Each save is a version in GitHub. Open the file → History → restore.

Backups

Your vault makes a weekly restore point on its own, and can mirror to a second host (GitLab, Codeberg) if you add one setting. See BACKUP.md in your vault.

Updates

Once a week your vault checks for kit updates (security fixes, skill improvements) and opens a pull request in your repo. It never touches your notes. Review it and click Merge.

No “Kit update” pull requests ever? Repo → Settings → Actions → General → Workflow permissions → tick “Allow GitHub Actions to create and approve pull requests” → Save. Then Actions → Vault template sync → Run workflow.

Teams & companies

The same kit runs one shared brain for a team. Three things change:

  • The vault lives in your company’s GitHub organization.
  • One person deploys once, on a paid Vercel plan (Pro or Team — Hobby is personal use only).
  • The workspace admin connects it for everyone — Claude Team/Enterprise via the admin console; ChatGPT Business/Enterprise via Plugins → Add → Add custom MCP server.

The passphrase stays with the admin. Members never need it. Rotate it to log every AI out.

Set up a folder per person plus one shared canon/ folder before anyone starts. Chiibitsu Labs does this live during team onboarding — labs@chiibitsu.com.

For your IT / CTO

This is not a source-code integration. No AI gets access to company repositories.

  • Notes are plain text files in one private GitHub repo, used purely as a filing cabinet.
  • The AI talks to a small connector on the user’s own Vercel account that can read, write and list notes — in that one repo only. No delete.
  • The GitHub credential is a fine-grained token for that single repo, Contents permission only.
  • Connecting an AI needs a human-held passphrase; AIs get a 30-day expiring token.

Worst case if everything leaked: one user’s notes repo. No code, no other repos, no org access. Every off-switch is in the user’s hands.

Data flow: a note the AI reads passes through Anthropic or OpenAI, same as pasting it into a chat.

Training: Claude Team/Enterprise and ChatGPT Business/Enterprise/Edu don’t train on your data by default. Personal plans (Claude Free/Pro/Max, ChatGPT Free/Plus/Pro) do unless you turn it off — Claude: Settings → Privacy; ChatGPT: Settings → Data controls.
